# CARDIODIAG research-extension roadmap

## Milestone 0 — Freeze the audit record

**Outputs:** this audit, provenance record, paper-to-code traceability table, and a clean note of pre-existing working-tree changes.

**Gate:** no implementation may overwrite the historical notebooks; all corrected experiments use separate modules and experiment IDs.

**Status:** completed for the initial local audit.

## Milestone 1 — Build a reproducible environment and data manifests

- Add a supported Python environment specification after confirming the available runtime.
- Record package versions, random seeds, operating-system details, and data hashes.
- Add acquisition instructions without committing restricted or large raw datasets.
- Add machine-readable data dictionaries and schema validators.

**Gate:** the two local CSVs load with deterministic schemas, target checks, row counts, missingness checks, and duplicate reports.

**Status:** completed for the supplied local datasets.

## Milestone 2 — Implement historical and corrected baselines

- Preserve a labelled historical reproduction of the original notebook logic.
- Implement a corrected pipeline using `Pipeline`/`ColumnTransformer`-style composition.
- Keep imputation, encoding, outlier treatment, feature selection, dimensionality reduction, and resampling inside the training folds.
- Compare no-resampling, SMOTE, and LoRAS only when the package and parameters can be pinned.

**Gate:** a synthetic leakage test proves that validation labels cannot change fitted preprocessing; resampling never touches validation/test rows.

**Status:** nested model selection is now implemented for the corrected candidates. A full resampling comparison remains because LoRAS parameters are not recoverable from the historical notebooks.

## Milestone 3 — Reimplement XAIH-DRC as a fold-local transformer

- Reproduce the paper’s Pearson/LIME/Spearman logic as closely as possible.
- Document all thresholds and categorical encodings.
- Add stability estimates over inner resamples.
- Decide whether the PCA branch is required using only training data and prespecified criteria.

**Gate:** transformer passes fit/transform tests, preserves feature names/semantics, and produces a saved selection-stability report.

**Status:** initial implementation completed. Reproduction against the paper's exact LIME workflow and a formal stability report remain.

## Milestone 4 — Implement the proposed stability-aware extension

- Add the provisional stability rule described in `docs/research_direction.md`.
- Use nested CV or a computationally bounded approximation with a documented budget.
- Keep the original OVEC and OSEC unchanged as comparison baselines.
- Add ablations: no XAIH-DRC, original XAIH-DRC, stability only, PCA only, and full proposed method.

**Gate:** all model decisions are frozen before the final internal holdout is opened.

**Status:** initial nested ablations completed for logistic, OVEC, OSEC, and stable-selector variants; no contribution claim is accepted because the stability selector is not uniformly better.

## Milestone 5 — Evaluation and uncertainty

- Report ROC-AUC, PR-AUC, sensitivity, specificity, precision, F1, balanced accuracy, confusion matrices, and prevalence.
- Add bootstrap confidence intervals and paired comparisons on identical observations.
- Measure Brier score, calibration intercept/slope, reliability curves, and ECE with a fixed binning rule.
- If feasible, add conformal/selective prediction with risk-coverage curves and explicit abstention.
- Evaluate explanation stability and perturbation sensitivity.

**Gate:** no metric is reported without sample sizes, class counts, split identity, and a machine-readable result record.

**Status:** nested fold means, fold variability, pooled outer predictions, bootstrap intervals, calibration summaries, repeated confidence/error ranking, selective-risk curves, split-conformal summaries, feature-set stability comparisons, and paired stability--reliability linkage are available. External-shift reliability remains pending.

## Milestone 6 — External validation or honest fallback

- Select and freeze the strongest accessible independent source before final model selection.
- Harmonize only features available at inference and document unavailable features.
- Apply the frozen pipeline without external-label tuning.
- If no valid independent source is available, report this as an explicit limitation and use the best feasible source only as a stress test/replication.

**Gate:** external results are generated by a one-way evaluation script that cannot fit or tune on external labels.

**Status:** the one-way evaluator is implemented and fails closed on the
template manifest. Execution remains blocked because no independent external
dataset has been frozen, and the repository intentionally refuses to treat the
supplied benchmark datasets as new external evidence.

## Milestone 7 — Manuscript and demonstration

- Generate tables/figures from result files.
- Draft the IEEE-style manuscript only after verified results exist.
- Include negative results, threats to validity, provenance, licenses, and a non-clinical-prototype warning.
- Add a small demonstration that shows prediction, confidence/abstention state, and explanation without implying clinical diagnosis.

**Gate:** tests, environment instructions, data manifests, experiment configs, result hashes, and manuscript references are internally consistent.
